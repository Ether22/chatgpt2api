## 第一轮确认记录

用户回复：“Q1是的 但是再新加一个筛选 能筛选出在途的；Q2按建议来”。下列建议已确认。

### Q1：“去除”的展示范围

“上游停用”不仅是统计卡，还用于账号健康筛选与行内标签；“监控额度”是顶部统计卡。

建议只删除两张统计卡。保留健康状态识别、对应筛选和仅监控账号功能，避免将删除统计展示解释为改变账号用途。

### Q2：“忽略”的可执行规则

建议条目上的“忽略”只解除阻挡，仍由底部生成按钮提交：

- 有 3 张参考声明、只能明确匹配 2 张时，按原声明顺序使用这 2 张；无法匹配或同名歧义的引用不送入生成。
- 没有可用参考图时，允许使用当前 Prompt 进行无参考图生成。
- 已经具有有效值的字段按当前显示值使用；空 Prompt、无效尺寸，以及无法确定实际生成内容的冲突仍需要修正，不凭空补造生成内容。
- 忽略结果随当前 MD 保存，刷新和切换会话后继续生效；重新上传 MD 时重新校验。条目显示简短“已忽略”状态，原始 MD 内容保留。
- 实际提交轮次仍保存实际使用的参考图及顺序。忽略当前导入错误不能改变已提交轮次。

已在 CONTEXT.md 定义“忽略条目错误”和“在途账号”。空 Prompt、无效尺寸等仍须修正。

## 已核实的实现事实

- [账号页](../../web/src/app/accounts/page.tsx) 顶部统计卡包含两项待删除文案。ZIP 同名文件的操作顺序为编辑、刷新、删除。
- [图库](../../web/src/app/image-manager/page.tsx) 当前“全选结果”确为纯文字 Button，不是方框被 CSS 隐藏；跨页收集已有实现，分页仅有前后页。
- [结果导航](../../web/src/app/image/components/image-navigation.tsx) 当前为来源条目、生成轮次、单图序号三级。
- ZIP 的 prompt-pack-import-dialog.tsx 使用紧凑布局；旧 image-composer.tsx 的数字输入与快捷数量处于同一网格。只取视觉参考，不回退其旧批次固定张数等业务逻辑。
- [导入解析](../../services/image_import_parser.py) 的错误包含引用问题、空 Prompt、无效尺寸、字段冲突等。[导入服务](../../services/image_import_service.py) 每次重新校验，并根据有效 matches 构造引用快照。因此只删错误文案不能让条目正常生成。
- [日志页](../../web/src/app/logs/page.tsx) 使用 [ImageThumbnail](../../web/src/components/image-thumbnail.tsx) 及普通 img 链接；新 managed 图片及缩略图接口要求 Authorization。图库已有 [useImageSource](../../web/src/store/image-conversations.ts) 可复用。
- [模型服务](../../services/model_service.py) 缓存默认 300 秒，签名依据账号类型与数量；账号刷新后单纯再调用现有读取接口不保证重查上游。
