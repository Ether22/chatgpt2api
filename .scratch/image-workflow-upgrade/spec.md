# 生图工作流、服务端历史与账号管理

## Problem Statement

用户需要在同一生图会话中连续处理普通 Prompt 和结构不同的 MD 图片任务，逐步上传参考图、选择条目、并发生成、比较多轮结果并可靠保存。当前长 Prompt 占据过多空间、图片按列错序、同会话轮次被串行处理，上传和轮询会重复传输参考图或重写整份浏览器历史，图库扩大后难以操作。

当前会话与参考图主要依赖浏览器保存，服务器尚未完整持有会话、来源条目、轮次及快照关系，不能满足跨浏览器恢复、身份隔离和可追溯复用。删除操作也缺少统一的物理清理和迟到结果处理，存在仅删页面记录、远端副本遗留及生成中删除后记录重新出现的风险。

账号列表需要区分消费用途、监控、禁用和隐藏，同时继续后台维护。现有自动移除账号、混合时间格式及过高的 OAuth 导入弹窗不符合用户的管理和操作需求。

本规格依据已完成的两轮确认，覆盖原需求 R01–R15。应用代码尚未修改，本次发布规格不撤回用户“先不修改代码”的限制。

## Solution

在当前生图会话中提供统一的普通生成与 MD 生成流程。用户通过双栏导入区管理当前 MD 和参考图，自动得到可编辑、可选择的条目预览；生成前严格校验尺寸和参考图，按条目准备进度启动对应任务，由已有账号池控制实际消费并发。

服务器负责身份隔离、当前素材、会话、轮次、不可被未来编辑改写的配置快照及图片关系。清空导入区不影响已提交轮次，同一会话同文档标识始终延续原来源条目；用户需要新产品时自行新建对话。结果按阅读顺序展示，以“条目 → 第 N 次 → 图片”导航，支持保留旧图的重跑、复用、当前轮下载以及准确的范围删除。

账号使用状态为正常使用、仅监控、禁用三种互斥选择，隐藏独立；监控与禁用都继续维护，但不承担消费请求。监控组固定在前、额度单独统计。业务日期统一北京时间，OAuth 弹窗的正文和操作区在有限窗口中均可到达。

## User Stories

以下每条均采用“作为某类用户，我希望某项能力，以便获得相应收益”的格式；编号用于追溯和验收。

### R01 Prompt 展示与图片顺序

1. 作为生图用户，我希望长 Prompt 默认只展示两行并可展开、收起，以便快速浏览多轮结果。
2. 作为生图用户，我希望折叠 Prompt 后仍看到参考图和任务标识，以便辨认结果来源。
3. 作为生图用户，我希望图片在所有响应式列数下按行依次显示 1、2、3、4，以便阅读顺序与图片编号一致。

### R02 同会话并发与上传流水线

4. 作为生图用户，我希望同一会话的不同轮次可以同时提交，以便继续工作而不等待上一轮结束。
5. 作为生图用户，我希望实际消费并发随现有账号池的可用容量变化，以便账号增减时不用修改固定账号数或固定槽位。
6. 作为生图用户，我希望账号忙或有明确恢复时间的额度、限流问题进入等待并说明原因，以便暂时无容量不会直接导致失败。
7. 作为生图用户，我希望没有合格消费账号或没有已知恢复时间时得到可重试的真实错误，以便知道需要处理账号还是重新提交。
8. 作为生图用户，我希望某条已选有效条目的参考图准备好就启动对应生成流程，以便其他条目继续上传时我也能开始获得结果。
9. 作为生图用户，我希望服务器先成功保存会话、轮次、任务归属和快照再发送生成请求，以便不会消费后才发现任务归属尚不存在。
10. 作为生图用户，我希望上传、轮询和保存不阻塞页面，以便生成期间仍能输入、切换和查看结果。
11. 作为生图用户，我希望相同参考图不因生成多张图片而被反复上传，历史和目录也不被逐图重复全量处理，以便批量生成更快。
12. 作为生图用户，我希望服务重启后续跑确定未发送的已保存任务，并先核实已发送但结果未知的任务，以便恢复工作而不重复消费。

### R03 MD 自动解析与预览

13. 作为 MD 生图用户，我希望自动提取每条的标识、名称、Prompt、尺寸、输出文件名和参考图声明，以便不必逐条复制填写。
14. 作为 MD 生图用户，我希望条目数由实际文档决定并支持双主图，以便不用迁就十九条或单主图的固定模板。
15. 作为 MD 生图用户，我希望支持 MAIN/SUB/A-D/A-M、P01/D01/M01、P01-A/P01-B 等标识，以便使用已有文档。
16. 作为 MD 生图用户，我希望支持标题尺寸、中文参考图字段、行内或嵌套文件列表及两种 Prompt 代码围栏，以便不同实际排版都能被正确解析。
17. 作为 MD 生图用户，我希望解析依据结构和明确字段而不调用 AI 猜测，以便生成配置可解释且可复核。
18. 作为 MD 生图用户，我希望明确“直通”或“无需生成”的段落不进入生成、预览和导航，以便不会误生成或增加无用条目。
19. 作为 MD 生图用户，我希望参考图文件名严格匹配且保持文档声明顺序，以便图片角色不会被猜测或调换。
20. 作为 MD 生图用户，我希望缺失参考图和同名冲突指出具体文件及条目，以便修复问题而不是接受静默覆盖。
21. 作为 MD 生图用户，我希望每条必须提供有效尺寸，缺失或无法识别时阻止该条生成，以便不会误用普通编辑框尺寸。
22. 作为 MD 生图用户，我希望开始前预览名称、实际提交的 Prompt、尺寸、匹配图片和错误，以便检查生成配置。
23. 作为 MD 生图用户，我希望能修正错误或跳过问题条目并生成其他已选有效条目，以便局部问题不阻塞整份文档。
24. 作为 MD 生图用户，我希望跳过表示不提交该条，以便系统不会把跳过误解为缺图仍强制生成。
25. 作为 MD 生图用户，我希望只有明确声明无参考图的条目才能无图生成，以便遗漏参考图字段不会被当成有效配置。
26. 作为 MD 生图用户，我希望冲突字段被标错、全局说明不被自动拼入 Prompt，以便预览和实际提交内容一致。
27. 作为生图用户，我希望结果显示实际尺寸且不提示与 MD 不一致，也不强制缩放、裁切或精准像素下载，以便直接保留上游原图。
28. 作为 MD 生图用户，我希望输出文件名可省略并获得可辨识名称，模型和画质沿用提交时的编辑框配置，以便减少重复设置而不改变生成选择。

### R04 数量与选择性生成

29. 作为生图用户，我希望首次默认生成 4 张，以便获得可比较的候选结果。
30. 作为生图用户，我希望用纯数字输入 1–100 的整数数量，以便精确控制本次生成张数。
31. 作为 MD 生图用户，我希望能统一设置整批数量，以便快速配置多个条目。
32. 作为 MD 生图用户，我希望每条能独立覆盖整批数量并清楚显示生效值，以便重点条目生成更多候选。
33. 作为生图用户，我希望后续手动选择的数量被记住，以便上传、解析和界面刷新时不会反复回到 4。
34. 作为 MD 生图用户，我希望只选择 SUB01 等部分条目，未选择条目也不显示“未生成”占位，以便结果区只呈现实际工作。
35. 作为生图用户，我希望逐条调整数量并重新生成且保留旧结果，以便比较多次尝试。

### R05 上传入口与拖拽

36. 作为生图用户，我希望普通上传右侧有“上传 MD 和参考图”入口，普通上传继续用于单次参考图，以便区分两种操作。
37. 作为 MD 生图用户，我希望左侧 MD、右侧参考图的双栏弹窗都支持点击和拖拽，以便方便地准备素材。
38. 作为 MD 生图用户，我希望弹窗展示文件列表、参考图数量、匹配结果、条目选择、数量和预览，以便集中完成生成准备。
39. 作为 MD 生图用户，我希望新 MD 直接替换当前 MD，以便不需要额外的“保存并替换”操作。
40. 作为 MD 生图用户，我希望多次加入参考图按追加处理并提示同名冲突，以便分批准备素材时不丢失旧文件。
41. 作为 MD 生图用户，我希望“清除上传内容”一次清掉当前 MD 和参考图，以便整套更换时操作明确。
42. 作为 MD 生图用户，我希望选择文件立即反馈、上传和解析显示进度及错误，长列表和窄屏可滚动，以便知道当前状态并能到达所有操作。

### R06 当前素材保存与清空

43. 作为生图用户，我希望每个登录身份只维护当前一份 MD 和一组参考图，以便不用管理多套素材历史。
44. 作为生图用户，我希望当前素材在服务器保存并被同身份的所有生图会话共享，以便切换会话仍能使用。
45. 作为生图用户，我希望不同身份的素材相互隔离，以便他人不能访问或修改我的导入内容。
46. 作为生图用户，我希望关闭弹窗、刷新和换浏览器后恢复当前素材，以便继续准备工作。
47. 作为生图用户，我希望创建任务、完成生成和关闭弹窗都不自动清空素材，以便由我决定何时删除或替换。
48. 作为生图用户，我希望替换 MD 只改变 MD，参考图继续追加，已提交轮次保留独立配置和有序快照，以便后续编辑不改变旧生成。
49. 作为生图用户，我希望清空或修改当前素材、删除一个会话都不破坏其他轮次和会话仍使用的文件，以便历史及在途任务保持完整。
50. 作为跨浏览器用户，我希望过期版本的素材修改提示冲突、无冲突新增可以合并而同名仍报错，以便同时操作不静默覆盖新内容。

### R07 对话归属与复用

51. 作为生图用户，我希望普通和 MD 生成都进入当前对话，没有当前对话时自动创建并继续，以便工作连续。
52. 作为生图用户，我希望并发首次提交只创建一个目标对话，以便同一组工作不被拆散。
53. 作为 MD 生图用户，我希望同一对话重新导入同标识时默认延续原条目，即使改文件、重写 Prompt 或清空过素材也一样，以便导航和来源不变。
54. 作为生图用户，我希望新产品由我自行新建对话，新对话中的同名标识独立，以便产品边界由我控制。
55. 作为 MD 生图用户，我希望重新导入更新未来配置而保留旧轮次原配置和图片，以便查看当时的真实生成条件。
56. 作为生图用户，我希望复用后即使修改 Prompt、尺寸和参考图仍继承来源条目，以便追溯原始工作。
57. 作为生图用户，我希望重跑、复用及再次复用都新增轮次而不覆盖旧图，以便比较结果且不产生无限来源层级。

### R08 右侧定位导航

58. 作为生图用户，我希望普通、MD、复用和重复生成全部进入右侧导航，以便统一查找结果。
59. 作为生图用户，我希望 MD 使用文档标识及名称，普通生成从 Prompt 本地提取短名，以便辨认条目而不额外调用 AI。
60. 作为生图用户，我希望导航按“条目名称 → 第 N 次 → 本次图片编号”组织并可折叠，以便查看生成历史而不是反复看到“复用”字样。
61. 作为生图用户，我希望点击父项名称定位最新一次、点击箭头只展开或收起，以便操作含义清楚。
62. 作为生图用户，我希望父组收起时仍提示当前位置，以便不会失去当前结果的归属。
63. 作为生图用户，我希望点击次数或图片准确定位并高亮、手动滚动也同步位置，以便导航与结果区一致。
64. 作为生图用户，我希望鼠标在右栏时只滚动右栏且所有底部内容可达，以便到顶到底时不带动中间结果区。
65. 作为生图用户，我希望点击未加载结果先取对应分页再定位，以便大型图库不必预载所有图片。
66. 作为窄屏用户，我希望有可用的定位抽屉，以便在小窗口仍能查找结果。

### R09 查看器与下载

67. 作为看图用户，我希望下载、批次下载、删除、尺寸、序号和关闭放在图片下方，以便操作集中且可达。
68. 作为看图用户，我希望“下载全部”仅包含当前生成轮次已经成功的图片，以便不会混入整段会话历史。
69. 作为看图用户，我希望逐张直接下载而不是 ZIP，以便直接使用生成文件。
70. 作为 MD 生图用户，我希望下载名称保留任务名称、图片编号及文档指定输出名主体，以便辨认图片用途。
71. 作为看图用户，我希望文件扩展名与实际图片格式一致，以便下载文件能被正确使用。
72. 作为参考图查看用户，我希望查看器只提供下载和关闭，以便不会误删作为输入的素材。
73. 作为生成结果查看用户，我希望查看器支持本轮下载和删除，以便管理当前结果。
74. 作为键盘用户，我希望 Delete 打开删除确认、Enter 确认、Esc 取消，以便安全地快速操作。
75. 作为看图用户，我希望删除后切换到相邻图片，以便继续查看同轮结果。
76. 作为看图用户，我希望删除最后一张后自动关闭查看器，以便不留空白界面。

### R10 删除完整性与性能

77. 作为生图用户，我希望单图、本轮结果、单个会话及全部历史按对应范围删除，以便不会误伤其他内容。
78. 作为生图用户，我希望会话旁按钮只删该会话、顶部入口清空当前身份全部会话且确认框说明范围，以便清楚删除影响。
79. 作为生图用户，我希望删除清理原图、缩略图、标签和已配置存储副本，以便不会仅移除页面记录而遗留文件。
80. 作为生图用户，我希望共享文件被其他轮次或当前素材引用时保留，最后引用释放后才物理删除，以便复用配置仍可工作。
81. 作为生图用户，我希望生成中删除立即隐藏并取消未启动任务，以便不再等待或消耗不需要的生成。
82. 作为生图用户，我希望无法中止的上游任务返回后自动清理迟到结果，以便没有孤儿文件。
83. 作为生图用户，我希望删除记录不被轮询或旧快照恢复，以便删除具有最终效果。
84. 作为生图用户，我希望确认后界面立即响应、清理在后台进行，以便大批删除不阻塞使用。
85. 作为生图用户，我希望清理失败显示真实原因、保留必要记录并允许重试，以便知道实际完成范围而不是收到虚假成功。
86. 作为生图用户，我希望已完成本地图片删除不做无意义取消，批量清理有限并发且避免重复删除和逐图重写全量索引，以便大量图片删除更快。
87. 作为生图用户，我希望纯 Prompt 隐藏和图片物理删除保持不同语义且配置仍可复用，以便隐藏展示不会破坏生成历史。

### R11 服务端历史与大型图库

88. 作为生图用户，我希望服务器保存会话、轮次、生成配置、参考图快照和结果关系，以便数据不依赖当前浏览器。
89. 作为跨浏览器用户，我希望同一身份能恢复历史、不同身份不能直接读取原图或缩略图，以便可用性与隔离一致。
90. 作为生图用户，我希望浏览器只保留界面偏好和必要缓存，以便不反复持久化整份 Base64 历史。
91. 作为大型图库用户，我希望结果分页、按需加载且导航轻量，以便打开和切换不等待全部历史加载。
92. 作为大型图库用户，我希望几千张图片时滚动、定位和删除仍流畅，以便历史增长后仍能继续使用。
93. 作为生图用户，我希望当前素材、快照和生成历史只通过明确删除操作释放，以便保留天数或磁盘不足不会自动删掉比较结果。
94. 作为生图用户，我希望磁盘不足时在消费前提示并阻止无法保存的生成，以便不会消耗额度后失去结果。

### R12 生图失败提示

95. 作为生图用户，我希望区分无可用账号、额度不足、上游超时、参考图读取失败和程序错误，以便知道失败原因而不只看到 HTTP 500。
96. 作为生图用户，我希望每张失败图片保留自身状态及可展开、可复制的技术详情和任务 ID，以便定位问题。
97. 作为生图用户，我希望技术详情脱敏，以便复制排查信息时不泄漏密钥或授权信息。
98. 作为生图用户，我希望同轮相同错误合并通知而仍保留逐图原因，以便批量失败时不会反复弹窗。

### R13 账号管理

99. 作为账号管理员，我希望正常使用、仅监控和禁用是互斥选择，以便一个账号只有明确的使用状态。
100. 作为账号管理员，我希望隐藏独立于使用状态，以便整理列表不会改变账号用途。
101. 作为账号管理员，我希望监控和禁用都继续自动额度刷新、监测和保活，但不参与生图、文本或搜索消费，以便维护账号而不使用它们的额度。
102. 作为账号管理员，我希望后台或手动刷新不能解除监控、禁用，以便上游状态变化不覆盖我的设置。
103. 作为账号管理员，我希望监控额度单独统计，监控与禁用都不计入可用剩余额度，以便判断实际可消费容量。
104. 作为账号管理员，我希望在现有编辑界面设置监控，不新增行开关或批量监控入口，以便保持列表简洁。
105. 作为账号管理员，我希望监控组固定在最前、其余账号在后，两组内部可拖拽排序并保存，以便持续监测重点账号。
106. 作为账号管理员，我希望监控账号有背景、色条、图标和悬停说明，以便快速识别状态。
107. 作为账号管理员，我希望隐藏账号默认不显示并能通过“显示隐藏账号”找回、取消隐藏，以便清理视觉干扰而不丢账号。
108. 作为账号管理员，我希望隐藏不影响请求资格、刷新和统计，以便展示选择没有业务副作用。
109. 作为账号管理员，我希望隐藏不影响原有导出规则，以便完整导出仍包含符合条件的账号。
110. 作为账号管理员，我希望移除账号物理删除入口、异常及限流只更新状态而不自动移除，以便账号始终保留供检查和恢复。
111. 作为账号管理员，我希望旧自动删除配置无效、旧 DELETE 请求明确拒绝，以便旧客户端也不能删除账号或得到假成功。

### R14 北京时间

112. 作为用户，我希望界面、业务 API、日志和业务文件日期统一北京时间并覆盖图片、账号、用户密钥和备份，以便跨功能对照时间。
113. 作为跨浏览器用户，我希望业务日期不随浏览器或服务器本地时区变化，以便换环境仍看到一致时间。
114. 作为用户，我希望内部瞬时计算和外部协议强制 UTC 的时间保持正确语义，以便时间展示调整不会影响鉴权、签名或超时。

### R15 OAuth 弹窗

115. 作为登录用户，我希望 OAuth 弹窗高度受可视区域限制，完成导入与取消始终可到达，以便不会因窗口过长而无法继续。
116. 作为登录用户，我希望长说明和授权 URL 可以滚动且完整 URL 仍可复制，以便保持现有授权操作能力。
117. 作为窄屏或键盘用户，我希望低高度、缩放和焦点切换下也能操作 OAuth 弹窗，以便窗口尺寸不阻断登录。

## Implementation Decisions

1. **身份与数据归属。** 复用已有稳定登录身份，不新增登录体系，不以浏览器、原始密钥或上游账号作为历史所有者。会话、来源条目、轮次、任务、素材、原图和缩略图的读写均在服务器校验归属；客户端提供对象标识不构成访问授权。

2. **持久化模型与存储复用。** 扩展现有生图任务和存储能力，服务器保存会话、来源条目、生成轮次、配置快照、有序参考图引用及任务/结果关系。当前素材每身份只有一份可变集合，旧轮次保存独立快照；物理文件可被多处引用，生命周期按有效引用管理。优先复用现有依赖和存储模式，不预设新数据库服务、消息队列中间件或固定生图线程槽位。

3. **来源条目与轮次身份。** 同会话同文档标识延续来源条目，内容改写、换 MD 文件或清空导入区都不拆组；新产品由用户自行新建会话。共享素材不合并不同会话的来源。复用继承来源并新增轮次；每轮保存提交时的名称、Prompt、模型、画质、尺寸、数量、输出命名与参考图快照。普通生成名称从 Prompt 本地提取，不用 AI；不得以名称或 Prompt 文本作为可变的唯一身份。

4. **MD 解析契约。** 按章节、明确字段和 Prompt 区块识别候选；标识族用于兼容实际格式，不定义固定条数、编号范围或主图数量。两种代码围栏、标题内尺寸/输出名、中文参考图字段和有序文件列表均需支持。明确的直通/无需生成控制仅作用于相应结构段落，Prompt 正文保持内容语义；全局说明不自动拼入。返回候选配置、匹配结果和逐条校验错误，预览展示实际提交内容。

5. **校验和选择契约。** 条目必须有有效目标尺寸、可用 Prompt 和明确的参考图声明；“无参考图”是显式选择，不能由字段缺失推断。声明的参考图按文件名严格匹配并保持顺序，缺图、同名及结构化字段冲突阻止对应条目；跳过/未选择条目不提交，也不建立结果占位。输出文件名可省略，缺省时按来源标识、任务名称及序号命名。首次数量为 4，用户数量选择保持，批量数与单条覆盖最终均校验为 1–100 整数。

6. **当前素材与上传契约。** 合并导入弹窗承载一份 MD 和追加的参考图；新 MD 直接替换 MD，清除动作一次移除当前 MD 与参考图，关闭/提交/完成不清空。保存后的文件以引用参与任务，避免每张结果重新上传同一份服务端素材；上游文件是否可复用服从真实账号和协议范围。多浏览器修改校验素材版本，过期替换/清空/修改返回冲突，无冲突新增可合并，同名仍拒绝静默覆盖。

7. **保存先于消费。** 创建/选定当前会话和提交操作须能处理并发与网络重试，重复请求不能重复创建目标会话、轮次或消费。只有所选条目自身参考图已就绪，并且服务器归属与快照保存成功后才调度上游；保存失败不得消费。用户明确开始后，各条按自身准备进度前进，不等待整份 MD 上传完成；页面不是已接受任务的生命周期所有者。

8. **并发、等待和恢复。** 解除会话级串行限制，复用已有账号池的实际资格和在途容量控制。忙碌或有明确恢复时间的暂时限流/额度耗尽保持等待；无合格消费账号或无已知恢复时间则返回可重试原因。重启续跑已保存且确定未发送的任务，已发送但结果未知的先核实；无法核实则保留中断/未知状态，不盲目重发。状态变更后的账号资格必须在下一次分配前重新生效。

9. **增量历史、导航和响应式结果。** 服务器对历史提供有限分页和下一页信息，导航读取轻量条目/轮次/图片标识及状态，不取全部图片字节；目标未加载时先加载对应分页再定位。浏览器仅保存界面偏好与必要缓存，轮询只落变化数据，不重写全量 Base64 历史。图片顺序由本轮逻辑序号决定，完成时间和响应式列数不改变编号。导航层级固定为来源条目、生成次数、图片；父项名称与折叠箭头具有独立行为。

10. **查看器、格式与下载。** 扩展现有共用查看器的上下文能力，参考图只有下载/关闭，生成结果提供当前轮成功图片下载与删除；控件位于图片下方。下载逐张进行，不调用 ZIP 批量下载，不扩展到整会话。文件名保留任务名称和序号，MD 指定主体保留，轮次等信息可用于避免重复名称，扩展名由真实格式确定。MD 尺寸只作请求目标，展示实际尺寸并下载原图，不作差异警告或自动像素变换。

11. **删除与文件保留。** 删除按单图、本轮、单会话和当前身份全部历史分层处理，导入区清空与历史清空独立。先让界面隐藏并停止未启动工作，再清理归属、原图、缩略图、标签和存储副本；其他有效引用仍存在时保留文件。删除状态阻止轮询或迟到结果恢复记录；不可中止的上游结果返回后自动清理。部分失败报告真实范围、保存重试所需信息，不能吞掉副本错误或恢复假可用图片。批量清理使用有限并发和批量元数据更新，已完成图片不做无意义取消。当前素材、快照和新图库历史不因保留天数或低磁盘自动删除；消费前检查无法保存的情况。纯 Prompt 隐藏保留配置，不等同物理删除。

12. **错误契约。** 沿用现有错误分类能力，服务端任务与 API 保留用户可理解的原因、可复制脱敏技术详情和任务 ID，前端不再丢弃结构化信息。每张图维护自身状态，同轮同类错误合并通知。登录密钥、上游令牌、OAuth code 和完整授权 URL 不进入可复制详情。

13. **账号使用状态与维护。** 正常使用、仅监控、禁用为互斥的使用选择，与上游健康/额度状态分开；隐藏仅影响列表可见性。监控与禁用继续自动额度刷新、状态监测和保活，所有生图、文本、搜索消费选择器及可用能力判断排除它们，刷新不能覆盖使用选择。监控额度单列且不计入可用剩余额度，禁用也不计入可用额度。监控组固定在前，非监控组在后，组内显式保存排序，不依赖令牌刷新后的插入顺序；设置留在现有编辑界面。

14. **账号保留与兼容请求。** 删除手动账号移除入口，停止所有异常或限流的自动删除路径，包括绕过共用删除逻辑的路径。旧自动删除配置及其界面入口不再生效；旧 DELETE 请求明确拒绝而不是假成功。隐藏不改变维护、统计、导出或本来由使用状态决定的消费资格。

15. **时间及 OAuth 布局。** 业务时间输出与展示使用无歧义的北京时间，不依赖浏览器/服务器默认时区；内部瞬时计算、JWT 和外部协议要求的 UTC 保持原语义。OAuth 修复集中于视口限高、正文滚动、长 URL 展示和操作区可达，不改授权流程，不强迫所有公共弹窗采用不必要的布局改动。

## Testing Decisions

用户已于 2026-09-08 确认以下验证方式。本节是后续实施的测试方案，本次未修改代码、运行生图或宣称测试已通过。

### 测试边界与方法

- **主要自动化边界是应用 HTTP 接口。** 从导入/预览、提交、查询、分页、文件读取、删除和账号管理等用户可观察入口发起请求，使用真实服务逻辑和隔离的临时持久存储；不要把被验证的完整任务服务替换掉后只断言一个成功响应。
- **只控制外部依赖。** 沿用已有可注入生成处理器、模拟上游与远端存储的能力，控制慢响应、失败、额度恢复和迟到结果。在同一行为场景中验证真实保存、引用和任务状态；无需真实消费上游额度。
- **保持测试边界数量少。** 已有任务服务公开操作可用于精确控制重启和竞态，作为接口场景必要补充；不为每个内部函数创建接口或单独套件。新素材/预览入口是产品能力，可在该入口验证解析，不额外建设只供测试的框架。
- **浏览器验证界面行为。** 检查上传反馈、数字输入、响应式排序、折叠、导航定位、滚动隔离、下载、删除快捷键、账号排序及 OAuth 可达性；布局和滚动不能只靠后端测试或截图快照认定正确。
- **好测试验证结果和约束。** 关注返回状态、可读历史、真实文件/副本、权限隔离、是否消费以及用户能否完成操作，不锁死私有方法、线程数量、内部字典、React 状态或存储布局。批量性能诊断记录传输量、全量写入和扫描次数，但不把偶然的内部函数调用顺序写成行为契约。

### 已有测试基础

- 现有 ImageTasksApiTests 使用 FastAPI TestClient 验证任务提交、多个图片输入和查询，是 HTTP 场景的既有组织方式；新增集成场景需让真实持久化与调度逻辑参与。
- 现有 ImageTaskServiceTests 已使用临时存储及可注入处理器覆盖重复提交、不同身份不能查询和新服务实例读取持久结果，可用于扩展保存屏障、重启和迟到结果。
- 现有 ImageStorageServiceTests 使用临时目录和 FakeWebDAVClient 验证本地、WebDAV 和双份存储，可扩展引用保护、物理删除和副本失败重试。
- 现有 AccountCapabilityTests、AccountExportTests 和身份服务测试可复用账号资格、额度及导出的场景基础。旧测试中“异常账号可被自动移除”和“启动时所有未完成任务统一失败”的断言与新规格冲突，需按确认行为调整，不能为了旧断言保留错误行为。
- 当前前端未发现独立自动化测试框架；优先完成浏览器行为验收和现有构建检查，不为可逆布局变更先引入新测试依赖。

### 行为验收矩阵

| 验证对象 | 关键场景与通过条件 |
| --- | --- |

| 身份与持久历史 | 不同身份无法读写对方会话、素材、任务、原图或缩略图；同身份新浏览器或新服务实例可以读取服务器数据；分页/导航不依赖全量图片字节。 |
| 保存与上传流水线 | 保存失败时无上游消费；重复提交不重复创建；一条参考图就绪即可生成，其他条目继续上传；同会话另轮可独立提交并由实时账号池限制消费。 |
| 等待与重启 | 忙碌或明确恢复时间进入等待，无合格账号返回真实原因；确定未发送任务可续跑，已发送未知任务不盲目重发。 |
| 来源与快照 | 同会话同标识在改写、换文件或清空后仍延续原条目；新会话同标识独立；再次复用不增加来源层级，旧配置和图片不变。 |
| 当前素材 | 关闭、刷新和生成完成都不清空；清空/替换/删除其他会话不损坏快照；同时编辑提示版本冲突，无冲突新增可合并且同名拒绝。 |
| 删除与保留 | 四种删除范围真实清理文件、缩略图、标签和副本；共享引用保护生效；生成中立即隐藏、未启动不消费、迟到结果清理且不复活；副本失败可报告与重试，无自动过期或低磁盘删历史。 |
| 错误反馈 | 无账号、额度、上游超时、参考图读取失败和程序异常有独立原因、任务 ID 及脱敏详情；同轮相同错误不反复弹窗，逐图状态不丢失。 |
| 结果与查看器 | 逐行编号、Prompt 两行折叠、下方操作及键盘删除行为正确；参考图仅下载/关闭；本轮下载只含成功图、逐张非 ZIP，名字主体与实际格式正确，尺寸差异不告警。 |
| 导航与大图库 | 数千张结果下打开、切换、滚动、折叠及跨页定位可完成，右栏不带动中间、底部可达，窄屏抽屉可用。对同一数据与环境记录耗时、页面响应、传输及写入/扫描成本，不把静态推断当成实测。 |
| 账号管理 | 三种使用状态互斥、隐藏独立；监控/禁用持续维护但全部消费路径排除，刷新不改设置；监控置顶、顺序保存、额度单列，隐藏不影响导出和统计；旧 DELETE 明确拒绝，异常/限流不删账号。 |
| 时间与 OAuth | 不同环境时区下业务日期为北京时间，协议 UTC 和瞬时计算正确；低高度、窄屏、缩放及长 URL 下提交/取消和焦点可达，完整 URL 仍能复制。 |

## Out of Scope

- 本次仅发布规格和整理实施任务，不修改应用代码、依赖或运行数据，不启动生成或执行重新部署。
- 不做旧 IndexedDB、历史数据或日期数据迁移，不提供认领、迁移向导或兼容导入；用户将重新部署。这不代表授权删除现有数据。
- 不用 AI 解析、补全 MD 或生成导航名称，不猜缺失图片/尺寸，不为缺图条目提供绕过校验的强制生成。
- 不根据文件变化、Prompt 内容、产品推断或清空素材自动新建对话或拆分来源；不引入多套当前导入素材历史。
- 不强制输出像素等于 MD、不提示尺寸差异、不自动裁切/缩放/补边，不将生成轮次下载做成 ZIP 或扩大为整会话下载。
- 不保留账号物理删除、异常/限流自动移除，也不增加行监控开关、批量监控入口或同时监控且禁用的组合。
- 不新增未经需要证明的登录体系、固定生图槽位、新中间件或测试框架；不更改外部协议强制 UTC 的语义。
