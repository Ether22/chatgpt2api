## 阶段 A 行为与接口

- 同会话轮次独立提交、独立线程调度，实际消费只由已有账号池 Condition/inflight 和配置的每账号容量控制。没有新增固定总槽位。公开服务与受控真实协议验证：两个账号同时发送两轮，第三轮等待；加入第三个合格账号后第三轮立即推进。
- 账号忙碌或明确、带时区的恢复时间进入等待；每次醒来重新检查用途/状态/型号资格。未知恢复时间或无合格账号返回真实可重试原因。远端验证失败保留原因，验证候选不再有固定 20 账号截断。账号保存通知等待者；等待进度的持久 I/O 在账号锁外执行。
- `ImageTaskService.start()` 由应用 lifespan 调用恢复；`shutdown(timeout=1)` 停止未发送工作的边界并限时等待本服务线程。正常关闭页面不取消服务端已接受任务。恢复只续跑 `dispatch_state=pending` 且具备持久 request 的任务。
- `submit_turn` 和独立 `submit_generation` / `submit_edit` 都先持久保存。普通轮次 request 保存有序 reference_ids，原 04 引用 pin 与会话/轮次/任务同事务；独立编辑 images/mask 保存必要的规范化字节、名称、MIME，不保存输入远程授权 URL。身份只存 id/name/role，不存登录密钥。
- 运行态 `lifecycle_callback(event, checkpoint)` 单独承载发送屏障和上游会话 checkpoint。Web 标记在真正 `/backend-api/f/conversation` POST 前，Codex 标记在 `urlopen` 前，均在上传/准备完成后；屏障保存失败会抛出，不允许吞掉后继续 POST。发送时再次检查本地可保存性。
- 已发送断线/超时禁止换账号或原账号重新生成。公开真实协议断线用例在旧实现捕获 4 次生成 POST，改后为 1 次，状态 unknown，retryable=false。明确 HTTP 401/429 拒绝仍更新原账号健康、释放在途容量并保留用途/隐藏/顺序；不会因不重发而绕过 17 的状态维护。
- 重启或 `resume_poll` 使用原上游账号的不透明持久引用。无会话 ID 时只按实际请求 message ID 精确核实最近 30 个会话，不按同名 Prompt/标题猜测；无法匹配保持未知。Web 使用原会话读取结果；Codex `store=false` 没有可靠查询接口，保持未知且不重发。受控验证涵盖匹配成功、只有同名无精确 ID 两种情况，均无新增生成 POST。原账号改为仅监控后仍可进行已消费结果的只读核实。

## 持久格式和协作边界

任务和图片索引均使用标准库 SQLite，传入 `.json` 路径只换后缀成为 `.sqlite3`，不会读取、覆盖或迁移旧 JSON。默认实际文件为 `data/image_tasks.sqlite3` 和 `data/image_index.sqlite3`。

表：`image_rows(namespace TEXT, key TEXT, value TEXT, PRIMARY KEY(namespace,key))`。value 为 JSON；SQLite 事务以 FULL 默认同步提交，提交异常不发布成功。任务库 namespaces：

| namespace | key / value |
| --- | --- |
| tasks | `owner_id:task_id`；保留原任务字典和附加字段 |
| conversations | 会话 ID；保留原 turns/sourceEntries 字典形状 |
| current | 登录身份 ID → 当前会话 ID |
| references | 引用 ID；04 scopes、turn_ids、最小 deleted 取消墓碑、upload_cancelled 原样保存 |
| inputs | 独立编辑的 `owner_id:task_id` → 必要 images/mask Base64 元组，仅在该任务恢复时读取 |
| images（图片索引库） | 原图片相对路径 → 原索引记录 |

`_tasks/_conversations/_references` 仍保留读方法依赖的内存字典语义。`_save_locked(*, tasks=(), conversations=(), current=(), references=(), inputs=None)` 只接受变化 key 集合并在同一事务保存；例：`_save_locked(tasks=[owner + ':' + task_id], conversations=[conversation_id])`。无参不再全量重写。10 可保留任务原 status/ordinal/条目，只追加 cleanup/tombstone 字段并显式传入变化任务/会话 key；任务更新合并旧字典，不会抹掉额外字段。

图片 `save` 直接 upsert 当前图，get/exists/delete 查询单行。`_load_index/_load_clean_index/_save_index` 形态保留供 13 读视图使用，批量保存也只更新值变化的行。

参考图上传、read、release 的外部文件/WebDAV I/O 已移出任务全局锁；同引用局部 RLock 串行，持久状态转换仍持全局 RLock。取消可在上传 I/O 期间先持久标记，迟到完成不得发布 ready。`submit_turn` 只在锁内核对 ready/pin 并保存，随后服务器工作线程读取参考文件。本轮 Future 只在内存共享一次读取/编码/04上传缓存，恢复从持久引用重建，不把 Future/锁/callback 写入 JSON。
