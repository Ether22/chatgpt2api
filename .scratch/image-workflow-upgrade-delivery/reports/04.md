## 范围与验收

- 普通参考图选择立即生成本地 Blob 预览，显示逐文件上传进度；未上传完成/失败不能提交，可重试或移除。服务端验证非空、50MB、真实 PNG/JPEG/WebP/GIF，不改变原始字节。前端不再读取 Base64 文件、不在轮次和轮询发送 Base64。
- `referenceImages` 提交只包含有序 `{id}`。服务器在同一次 JSON 原子保存中记录来源、轮次、任务及不可变公开参考快照 `{id,name,type,url,size}`，并为每个文件登记该轮次 ID。Prompt、模型、尺寸、画质、数量仍保存原提交值。修改输入、重新上传、释放输入不会改写旧轮次。
- 参考图与结果物理区分：`managed/<owner hash>/references/<北京时间 YYYY/MM/DD>/<uuid>.<真实扩展名>`，图片索引 `kind="reference"`、`mime_type`；结果沿用03路径/未指定 kind。参考原图、缩略图沿用03保护路由与安全路径，不向任意结果 URL 主机转发登录密钥。已通知13按 kind 和路径排除参考图；本票不改图库遍历/筛选、会话分页读接口或 `useImageSource`。
- 普通上传记录在写文件前先保存 `state=pending`、预定路径、摘要、文件名、登录身份、原存储模式和远端目标。物理文件及索引保存成功后才标记 ready。任一阶段失败仍可用相同上传 request_id 重试；摘要/文件名不符拒绝覆盖；pending 不能生成。重载后 pending 在输入列表显示错误，可移除。无需失败后再写一个独立孤儿账本。
- 物理目标按原 mode 和 WebDAV URL/root/username 校验；密码刷新不视为目标变化。目标变化时拒绝把上传/删除重定向到新位置，提示恢复原位置再重试。失败副本记录保留，最后引用释放失败后可通过同一 DELETE 重试；索引没有成功写入时也按 pending 中的原目标尝试清理。
- 输入分为独立 `ordinary`、`imports` 两个 scope；同一身份每个 scope 是逻辑集合，重复持有幂等。普通 HTTP 只操作 ordinary；06可通过公开服务方法使用 imports。每轮 `turn_ids` 独立于输入 scope，重复文件 ID 不重复计同一轮。未提交普通输入保存在服务器，同身份刷新/再次打开恢复；不会因离开页面、保留天数或低磁盘自动删除。用户移除、清空编辑框或提交确认后释放 ordinary；提交中的输入暂不释放，避免保存前删除。
- 复用配置/将历史参考加入编辑先 retain ordinary；移除 imports 或删除最后历史轮次不能破坏还在 ordinary 编辑的输入。参考查看器下载使用原文件名主体与真实扩展名，只有既有下载/关闭行为，不提前实施12的查看器布局。
- JSON `/v1/images/edits` 和 `/api/image-tasks/edits` 接受 `{file_id: <本服务参考ID>}`，以当前登录身份解析原字节；未知/其他身份/裸上游 file_id 被拒绝。原 multipart、Base64 与远程 URL 输入继续支持。普通轮次不再接受旧 dataUrl 快照字段，不迁移旧数据。

## 上游协议与性能边界

实际链路：`submit_turn` → `openai_v1_image_edit.handle` → `ConversationRequest` → 现有账号池分配 token → `OpenAIBackendAPI._stream_picture_conversation` → `_upload_image` → Web multimodal 文件协议。`_api_messages_to_conversation_messages` 也调用 `_upload_image`，已覆盖共享入口；可编辑文件专用 `_upload_editable_base64_image` 未被改写。

- 本轮只编码一次输入图片，100个排队单图任务共享同一不可变编码列表。原始字节也是同一份 payload，不创建100份持久 Base64。
- `ImageUploadCache` 只在本轮运行态 payload 存活，键包含实际发送的 Authorization 摘要、上游 base URL、ChatGPT 租户 header、`backend-api/files:multimodal` 协议、内容摘要和文件名。仅在文件上传/确认成功后缓存结果。同键使用 Future 合并在途上传，网络操作不持有缓存索引锁，异账号无需等待同一把上传锁。失败会发布异常并移除缓存项，等待者和重试都能结束。
- 不全局、不跨轮次、不跨登录身份、不持久化裸上游 file_id。单个 `/v1/images/edits` 请求内的 n 个结果也可共享该缓存。
- Codex 当前 `/backend-api/codex/responses` 使用 `input_image.image_url` 内联内容，没有接入 Web 文件 ID 的协议。受控公开协议测试捕获两次真实构造请求，仍分别内联，零 Web 上传、零 Web file_id。本票不臆造 Codex 文件引用能力；浏览器→本服务仍只上传一次，但 Codex 协议请求自身仍携带输入图。
- JSON/Future/回调绝不混存：`encoded_images`、`image_upload_cache`、Future 和 `progress_callback` 仅运行态，05恢复时需根据已保存文件 ID 重建，不能直接序列化 payload。

## 可供06/10/11复用的接口

HTTP：

| 操作 | 契约 |
| --- | --- |
| `POST /api/image-references` | multipart `file` + `request_id`，返回 `{id,name,type,url,size}`；上传重试幂等，默认 ordinary |
| `GET /api/image-references` | `{items:[公开参考字段+可选error]}`，只列当前身份 ordinary，包含可重试 pending/清理失败 |
| `POST /api/image-references/{id}/retain` | 持有 ordinary，返回公开参考；历史输入复用前调用 |
| `DELETE /api/image-references/{id}` | 释放 ordinary；返回 `{retained:true}` 表示其他 scope/轮次仍持有，`false` 表示全部副本已清理；错误真实返回，可重复 DELETE |
| `POST /api/image-conversations/turns` | `referenceImages:[{id},...]`，只接受本身份 ready 文件，保存不可变有序公开快照 |

公开服务方法均在既有 `ImageTaskService` 上：

- `upload_reference(identity, request_id, data, name, base_url="", *, scope="ordinary")`；06上传传 `scope="imports"`。
- `list_references(identity, *, scope="ordinary")`、`retain_reference(identity, reference_id, *, scope="ordinary")`、`release_reference(identity, reference_id, *, scope="ordinary")`。仅支持 ordinary/imports，不把原始登录密钥当归属键。
- `read_reference(identity, reference_id)` → `(bytes, name, mime)`，拒绝 pending/无有效持有者。
- `release_turn_reference(identity, reference_id, turn_id)`：供10/11在移除对应轮次/会话且任务已终结后逐个释放快照 ID；活跃可见轮次和非终态任务拒绝释放。最后引用才清文件、缩略图和副本；可用相同 ID 重试失败。不自动遍历删除历史，本票不接入10/11用户删除操作。

生命周期仍使用原锁/原 tasks JSON 快照，新增顶层 `references`。无需06另造计数账本；共享素材版本和当前 MD 元数据仍由06独立实现。05若改变持久层，应保留这些公开方法和“轮次/引用同事务保存”的约束。
