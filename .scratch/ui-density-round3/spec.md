# 界面密度与刷新反馈第三轮

状态：2026-09-10，七项需求已完成并通过验证，详见 [验收记录](validation.md)。用户追加修正已落实：图片按数量自适应，4 张采用 2×2，6 张采用 3×2，最多三列。Prompt 采用左对齐浅底内容块。

## 方案

| 项目 | 拟实施行为 |
|---|---|
| 基础配置对齐 | 输入项成对排列，开关单独成组；标签、输入控件和列边界对齐，移除无效占位及布局空洞。 |
| 号池背景 | 恢复与其他页面一致的米色背景。普通账号行不额外铺纯白底，拖动时仍有清晰底色，监控行保留提示色。共同渐变固定到视口，短页与长页验证通过。 |
| 生图图片紧凑 | 按实际图片数量自适应：1 张单列且限制宽度，2/4 张双列，3/5/6 张及更多最多三列；4 张为 2×2，6 张为 3×2。手机最多两列。缩略图统一约 224px 高，手机 160px，保留完整比例。成功、加载中和失败卡片采用一致的紧凑空间，图片顺序不变，点击预览原有大图。 |
| 图片预览 | 删除“打开原图”。切换时保留上一张已显示图片，目标图加载并解码后再替换；失败有提示和重试，连续切图不允许迟到结果覆盖最新目标。等待期间明确显示加载状态，防止旧画面与新目标的下载、删除操作错配。关闭、身份变更或图片已删除时正确释放及隐藏旧图。 |
| 可用剩余额度 | 显示精确整数，沿用现有全池实时统计；刷新单个、选中和全部账号均即时反映真实变化。恢复成功后查询新额度，结束及失败时同步最新账号，避免回退到旧快照。账号用途和可消费额度的统计范围不变。 |
| Prompt 样式 | 用户确认整行左对齐的浅底内容块，默认两行，标题栏放展开/收起与复用配置，展开在原位置显示全文；必要元信息和删除入口保留。 |
| 顶部轮数 | 删除生图页面顶部“共 N 轮”汇总及由它留下的空白，保留小屏定位入口、加载反馈和每轮内部的必要标识。 |

## 本轮确认

- Q1：用户先选择双列，随后明确改为按数量自适应、最多三列；以最后修正为准。
- Q2：用户选择左对齐浅底内容块。

## 已核对的事实

- 基础配置把带标签的输入框与没有上方标签的复选卡放在同一网格行，产生错位；部分整行占位进一步制造空洞。
- 号池外层没有独立白色页面背景，但普通可拖动账号行有纯白底。共同径向渐变以整页高度计算，长页面首屏偏白已通过离线合成页面复现；固定 html/body/main 的背景后，明暗主题的 3/20/100 行首屏取色一致，详见 [背景验证](background-probe/validation.md)。
- 预览切图时旧 img 节点被重建，受保护图片地址被清空，旧 blob URL 被释放，新请求及解码尚未完成；图库跨页请求阶段本身保留旧列表。
- 额度统计已有每轮约 300ms 等待的进度轮询，并实时计算全账号可用额度。20,001 和 20,049 等不同值都可能被简写成 20.0k；恢复线程尚未读取新额度；进度请求失败清除实时统计后会回到旧账号快照。
- 生图现有桌面网格使用可拉伸的大尺寸列，纵向图片按原比例增高；Prompt 容器和正文均右对齐。

## 验收重点

- 同一视口下，号池短页、20/100 条长页与其他页面背景一致。
- 配置输入框和开关在桌面及小屏整齐排列。
- 单张、横图、竖图、多图、加载与失败状态均紧凑且操作可达；长 Prompt 左对齐，展开收起稳定。
- 慢图片同页/跨页切换无空白闪黑，连续切换不乱序，失败可重试；下载/删除不与屏幕图片错配，删除或身份变更不残留旧图。
- 额度变化在批次未结束时可见，恢复成功后的额度更新，刷新失败不回退旧值。
- 顶部总轮数及“打开原图”入口消失，既有核心交互和身份隔离保留。

验证使用当前源码、隔离运行环境与合成数据。实施基于 Git `95610fa`，保留其他已提交修改。本轮不需要新增 ADR。
