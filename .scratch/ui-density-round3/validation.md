# 界面密度与刷新反馈第三轮验收

2026-09-10，七项调整完成。

| 范围 | 最终行为 |
|---|---|
| 基础配置 | 输入项成对排列，开关连续排列；标签和输入框对齐，选择框占满所属列，日志级别跨两列，移除无效占位。 |
| 号池背景 | html/body/main 的渐变固定到视口，避免长页面首屏变白；普通账号行透明，监控行保留浅黄色，拖动时提供清晰底色。 |
| 生图结果 | 根据实际数量排布：单张限制宽度，2/4 张两列，其他多图最多三列；4 张 2×2、6 张 3×2。手机最多两列。图片区域桌面 224px、手机 160px，高度稳定且保留完整比例；加载及失败区域同样紧凑。 |
| 图片预览 | 删除“打开原图”。在新图加载并解码后替换旧图，同页和跨页等待期间保留旧画面并显示加载提示；阻止等待期间的下载、删除和 Delete 快捷键错配。迟到请求不覆盖当前目标，失败可重试，删除、身份变更和权限失效时清除旧画面；关闭或替换时释放自建 blob URL。公开外部图片继续使用原生图片加载。 |
| 剩余额度 | 显示精确整数及千位分隔符；已有全池进度统计即时显示。密码恢复成功后读取新额度，完成和失败时重新同步账号；同步失败保留最近有效统计。监控、禁用、异常和限流账号的消费统计规则保持一致。 |
| Prompt | 改为整行左对齐的浅底内容块，默认两行；标题栏提供展开/收起、复用配置和删除入口，必要轮次信息保留。 |
| 顶部轮数 | 删除生图顶部“共 N 轮”以及桌面空白行，小屏定位入口和加载反馈仍可用。 |

## 验证

- 27 项后端检查通过：账号保留、恢复成功后实际读取额度、额度查询失败保留新凭据、普通/监控/禁用用途统计、账号使用状态和排序。新增恢复检查覆盖六组成功/失败与用途组合，确保额度查询完成前进度不会提前结束。
- TypeScript 独立检查和生产构建通过，生成 11 个静态页面。
- [本轮浏览器检查](../../test/image_ui_density_browser.cjs)通过：20,001 → 20,049 在批次未结束时可见；单个、选中、全部刷新和恢复；进度与账号重载同时失败时不回退旧值；配置在 1440px 和 390px 下对齐；4/6 张排列、长 Prompt 折叠；慢图保留、连续切换丢弃迟到响应、失败重试、删除后隐藏、403 权限变化、身份变更。
- [图库回归](../../test/image_gallery_migration_browser.cjs)通过：第 12/13 张双向跨页，跨页慢图保留旧画面，下载失败重试，日期及标签选择。
- [第二轮回归](../../test/image_ui_refinement_browser.cjs)通过：号池每页数量保存、筛选、350 张分批全选及取消/失败保留、紧凑预览与 320×360 小屏、参考图声明修正和结果定位。
- [原生图片检查](native-preview-check.cjs)通过：无 CORS 响应头的公开外部图片、data URL 均可预览，外部图片主机不收到身份密钥。
- [背景取色验证](background-probe/validation.md)通过：明暗主题在 3/20/100 行首屏的取色一致。
- 已查看桌面、手机、慢图等待截图。9 个应用文件与 3 个测试文件均和受检副本一致，`git diff --check` 通过。
