# 号池背景颜色离线验证

2026-09-10；Chromium，1440 × 1000；页面仅含合成文字和占位卡片，无应用脚本，阻断全部网络。使用隔离构建的实际编译 CSS 和最新 `layout.tsx` 的 `main` 类名；源目录及隔离目录的 `globals.css`、`layout.tsx` SHA-256 分别一致。

结论：已复现“长号池页面首屏变白”。不是账号页面另设了白色页面背景。现有 html、body、main 的径向渐变按文档高度定位；增加行数就会把首屏推向渐变的白色起点。固定全部三层到视口后，相同视口的 3、20、100 行首屏外侧取样点完全一致。浅色和深色均通过。

| --- | ---: | ---: | --- | --- |

`main` 背景带透明度，仅给它加 `bg-fixed` 仍会叠加 html/body 随整页高度改变的渐变。最少修复可在 `globals.css` 的 `@layer base` 块外添加下列一条声明，覆盖三个层次的 background-attachment，而保留现有渐变颜色和暗色定义：

```css
html,
body,
main {
  background-attachment: fixed;
}
```

若要留在 `@layer base` 内，应放在现有 `.dark, .dark body` 背景声明之后，并使用 `:root, :root body, main`，避免暗色 `background` shorthand 的优先级把 attachment 重置为 scroll；本次实际跑通的是上面的无 layer 规则。

三层固定后滚动到页面底部仍有最多 2/255 的通道差；本验证不声称跨滚动位置逐像素一致。已确认的保证是不同页长的同一首屏取样完全一致。表格行自身的白底保持原样，不影响这次外侧背景结论。

可运行检查：`node .scratch/ui-density-round3/background-probe/check.cjs`。36 张截图和完整取样、样式在同目录 `results.json`。脚本退出 0，检查两种主题均能复现当前缺陷且三层固定后首屏不再随页长变化。
